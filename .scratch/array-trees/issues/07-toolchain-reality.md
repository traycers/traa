## Question

Пользователь называет две C++ реализации («на базе parallel STL и на базе boost.simd») и две Go реализации («на базе стандартной библиотеки и simd пакета», Go 1.27). Быстрая проверка окружения уже показала повод усомниться:

- `go version` в этом окружении даёт `go1.26.0`, не 1.27.
- В `cxx/.devcontainer`/`cxx/Dockerfile.dev` Boost вообще не установлен (только build-essential/cmake/ninja/gtest/gmock/clang); `cxx/traaxx/CMakeLists.txt` содержит только закомментированную заглушку `# Boost::headers`.
- Boost.SIMD как таковой не был принят в Boost (проект не вошёл в состав библиотеки); живые преемники — xsimd, Google Highway, `std::experimental::simd`/будущий `std::simd` (C++26).
- SIMD-работа в Go шла как `internal/simd` под `GOEXPERIMENT=simd` (amd64/AVX-512) — не факт, что это публичный пакет, доступный обычному коду.

Нужно точно установить: какая версия Go сейчас доступна и когда/если станет доступен Go 1.27; существует ли публичный Go `simd`-пакет и на каких условиях (build tag, GOEXPERIMENT, доступные архитектуры); какая библиотека реально стоит за словами «boost.simd» в этом проекте — сам мёртвый Boost.SIMD, один из преемников (xsimd/Highway), или `std::experimental::simd`/`std::simd`; что из этого нужно доустановить в `cxx/Dockerfile.dev`/devcontainer, и в каком виде параллельная STL-реализация будет собираться (libstdc++ `<execution>` требует TBB на некоторых тулчейнах — проверить, поставлен ли TBB и/или доступен ли `<execution>` без него на этом clang/libstdc++).

## Answer

Полный отчёт с источниками — `research/07-toolchain-reality.md`. Выжимка (research-агент, проверено по официальным источникам go.dev/gcc.gnu.org/boost.org/README библиотек, дата исследования — 2026-09-03):

1. **Go версии.** Локально `go1.26.0`. По `go.dev/doc/devel/release`: Go 1.27.0 вышла **2026-08-19** (1.27.1 — 2026-09-01) — на момент этого исследования уже реальный релиз, не будущая/несуществующая версия. Локальное отставание на одну минорную версию — вопрос апгрейда тулчейна.
2. **Go `simd`.** Два публичных (не `internal/`) пакета под предложением golang/go#73787 (Proposal-Accepted): `simd/archsimd` (архитектурно-специфичный, с Go 1.26, amd64 128/256/512-бит) и портируемый верхнеуровневый `simd` (golang/go#78902, с Go **1.27**, доступен на всех архитектурах, падает на software-эмуляцию без аппаратной поддержки). **Оба** требуют явного `GOEXPERIMENT=simd` при сборке и оба имеют официально нестабильный API. Пользователь имел в виду именно портируемый `simd` (Go 1.27) — он существует, но версия и `GOEXPERIMENT`-флаг должны быть явно зафиксированы в спецификации как принятый риск.
3. **Boost.SIMD.** Подтверждено мёртв: никогда не был принят в Boost (вырос из проекта NT2, review 2014 года не завершился принятием), позже стал коммерческим bSIMD. **Формулировку «boost.simd» нужно заменить.** Живые кандидаты: `std::experimental::simd` (Parallelism TS2 — уже физически есть в системном GCC этого окружения, `/usr/include/c++/15/experimental/simd`, ничего доустанавливать не нужно, но API — TS-версии, не финальный C++26 `std::simd`, которого в GCC пока нет полностью и который требует `-std=c++26`, тогда как `cxx/CMakeLists.txt` собирается под C++23); **xsimd** (header-only, BSD-3, зрелая, нужно завести в `Dockerfile.dev`+`CMakeLists.txt`); Google Highway (не header-only, самая широкая платформенная поддержка, более тяжёлая интеграция). Финальный выбор между ними вынесен в отдельный тикет `[[14-cxx-simd-library-choice]]` — это архитектурное решение, не факт.
4. **Parallel STL.** Официальная документация GCC (`gcc.gnu.org/.../status.html`) подтверждает жёсткую зависимость `<execution>` от Intel TBB 2018+ начиная с GCC 9.1, **без исключения в более новых версиях** — предположение о том, что современный GCC мог отказаться от этого требования, не подтвердилось. Локально есть только рантайм TBB (`libtbb12` и т.п.), но не `libtbb-dev` — для сборки parallel-STL-реализации `libtbb-dev` нужно явно добавить в `Dockerfile.dev` и подключить `find_package(TBB)`+линковку в CMake. `<execution>` физически доступен на связке "clang + системный libstdc++" (тот же дистрибутив заголовков GCC, где нашёлся и `experimental/simd`), TBB-зависимость идёт от libstdc++, а не от компилятора.
5. **Состояние репозитория.** Сейчас чистый каркас: `PROJECT_DEPS` в `cxx/CMakeLists.txt` пуст, единственное упоминание внешней C++-зависимости — закомментированная и всё равно неверная строка `# Boost::headers` в `cxx/traaxx/CMakeLists.txt`. `Dockerfile.dev` не ставит ни Boost, ни TBB dev-пакет, ни SIMD-библиотеку. `CMAKE_CXX_STANDARD` — 23 (не 26).

**Практический вывод для карты**: формулировка «две C++ реализации (parallel STL / boost.simd)» становится «parallel STL (требует доустановки `libtbb-dev` + `find_package(TBB)`) / SIMD-реализация на `std::experimental::simd` **или** xsimd (выбор — `[[14-cxx-simd-library-choice]]`)»; формулировка «Go simd, целевая версия Go 1.27» остаётся в силе как есть, с пометкой «`GOEXPERIMENT=simd`, API нестабилен — принятый риск».
