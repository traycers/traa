## Question

`08-array-trees.md` §4–§11 описывает широкий набор операций над array-based деревом: производные вектора, распространение маски (вниз/вверх, однопроходная/итеративная/pointer doubling стратегии), DFS- и BFS-переупорядочивание, LCA (наивный подъём, binary lifting, пакетный вариант, LCA множества), мутации (`append`, удаление листа, удаление поддерева+компактификация, splice out, перемещение), валидация инвариантов §13.

Весь этот набор входит в обязательный набор операций, которые должны поддержать (и по которым сравниваются) все 4 реализации, или для первой версии нужен меньший набор?

## Answer

**Весь набор из §4–§11**, без урезания:

- Производные вектора: `depth`, `rank`, `size`, `nsibling`, `lastchild`, `isleaf`, `pos` (DFS/BFS-позиция).
- Распространение маски по `parent` — все три стратегии отдельно (не только «быстрейшая»): однопроходная (§5.3, требует инвариант порядка), итеративная до сходимости (§5.1–§5.2), pointer doubling (§5.4). Именно разные стратегии распространения — то место, где параллельные/SIMD-реализации расходятся по конструкции с последовательной, поэтому все три обязательны для содержательного сравнения.
- Переупорядочивание: DFS (способ Б, §8.2, размеры+смещения) и BFS (§9.1 или §9.2).
- LCA: наивный подъём (§10.3), binary lifting (§10.4), пакетный вариант для m пар (§10.5), LCA целого множества (§10.6).
- Мутации: `append` (§11.2), логическое удаление листа (§11.4), удаление поддерева с компактификацией (§11.5), splice out (§11.6), перемещение узла/поддерева (§11.7).
- Валидация инвариантов §13 целиком (как отдельная проверяемая операция, не только внутренняя проверка).

Обоснование: разные операции нагружают разное железо (однопроходная версия — последовательная цепочка зависимостей, итеративная и pointer doubling — параллельны и SIMD-дружественны, §5.3 note) — усечение набора спрятало бы именно ту разницу, ради которой затевается сравнение parallel STL / boost.simd-or-successor / Go stdlib / Go simd.
