## Question

Как две C++ реализации сосуществуют внутри `cxx/traaxx/` (и как их видит `cxx/tests/t_traaxx/`), и как две Go реализации сосуществуют внутри `go/` — раздельные CMake-таргеты/namespace'ы, раздельные Go-модули/пакеты, отдельные поддиректории?

`[[07-toolchain-reality]]` закрыл фактическую часть: Go-сторона устоялась (портируемый пакет `simd`, Go 1.27, обязательный `GOEXPERIMENT=simd`, нестабильный API — принятый риск), а для C++ вместо мёртвого «boost.simd» остаются живые кандидаты (`std::experimental::simd` / xsimd / Highway) без финального выбора. Именно этот выбор — `[[14-cxx-simd-library-choice]]` — определяет, что подключать в `cxx/cmake/files/find_deps.cmake`/`find_pkgs.cmake` (header-only xsimd vs готовый системный `std::experimental::simd` vs собираемый Highway) и как это отражается в раскладке `cxx/traaxx/`.

## Answer

Факт на входе (чтение `cxx/CMakeLists.txt`/`cxx/traaxx/CMakeLists.txt`): сейчас в `cxx/` ровно один таргет `traaxx` (статическая библиотека `demo::traaxx`), один `traapp` (`main.cpp`), один тестовый таргет `t_traaxx` — чистый каркас на одну реализацию, ничего под вторую не заведено.

### C++

- **Две библиотеки, два верхнеуровневых CMake-таргета**: `cxx/traaxx` (parallel STL, существующее имя и каталог не переименовываются) и `cxx/traaxx_simd` (xsimd, новый каталог/таргет). Не вложенные подкаталоги одного родителя — независимые таргеты рядом.
- **Один CLI-раннер `cxx/traapp`**, один `main.cpp`, линкуется с **обеими** библиотеками одновременно; выбор реализации — новый флаг `--impl {std,simd}` (`std` = parallel STL, `simd` = xsimd), диспетчеризация в runtime. Не два раздельных бинарника/копии `main.cpp` — CLI-логика (парсинг флагов, чтение JSON, цикл замера) одна на оба impl, различается только то, какую библиотеку дерева она вызывает.
- **Тесты — два отдельных таргета**, зеркально библиотекам: `t_traaxx` (линкует `traaxx`) и `t_traaxx_simd` (линкует `traaxx_simd`), без общей параметризованной GTest-машинерии между ними. Сравнение реализаций между собой — работа внешнего CLI-драйвера (`[[09-cli-schema-details]]`) и golden (`[[08-json-schema]]`), не GTest; здесь тестируется внутренняя корректность конкретной реализации.

### Go

Симметрично C++, для единообразия сравнения: один модуль `go/`, два внутренних пакета реализации (`std`, `simd` — те же имена, что и значения `--impl`), один бинарник `cmd/traago` с тем же `--impl {std,simd}`, диспетчеризующим на нужный пакет.

### Единый флаг `--impl`

`--impl {std,simd}` — одинаковый enum для обоих раннеров (C++ и Go), одинаковые значения независимо от того, что физически стоит за ними на каждом языке.

### Правка `[[09-cli-schema-details]]`

Добавляется обязательный флаг `--impl {std,simd}` во все режимы вызова (одиночный `--tree`/`--case` и батч `--manifest`) — раньше выбор реализации подразумевался выбором бинарника (2×C++, 2×Go — 4 разных бинарника), теперь один бинарник на язык обслуживает обе реализации этого языка, и `--impl` стал обязательным для различения.
