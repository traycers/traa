## Question

Чтобы сравнивать корректность и скорость всех 4 реализаций однообразно, нужен ли единый внешний контракт (например, CLI с JSON на входе/выходе: дерево + операция → результат + время/число проходов), который каждая реализация реализует одинаково, а внешний драйвер сравнивает результаты с golden и собирает метрики? Или у каждого языка свой тестовый ранер?

## Answer

**Единый CLI-контракт**, один и тот же набор флагов/формата ввода-вывода для всех 4 реализаций (2×C++, 2×Go). Каждая реализация собирается в бинарник-раннер, который:

1. принимает путь/JSON корпусного дерева (`[[04-corpus-golden-format]]`) и имя операции (`[[02-operation-set]]`) плюс её параметры;
2. выполняет операцию;
3. отдаёт результат и метрики (время, число проходов/итераций — важно для операций с несколькими стратегиями propagation, см. `[[02-operation-set]]`) в одном и том же JSON-формате.

Внешний (языконезависимый) драйвер — единственное место, где живёт логика сравнения с golden и агрегации в хранилище метрик (`[[06-benchmark-storage]]`). Логика сравнения не дублируется в четырёх экземплярах — меньше риска, что баг в тестовом ранере одной реализации незаметно исказит сравнение.

Открыто (см. Not yet specified карты): точный набор подкоманд/флагов, конверт вывода (структура result+timing+iterations), конвенция кодов возврата/ошибок.

Контекст: `[[02-operation-set]]`, `[[04-corpus-golden-format]]`, `[[06-benchmark-storage]]`.
