## Question

`docs/learning/array-trees/` содержит набор характерных форм дерева, каждая высвечивает своё свойство представления `parent`+`sibling` (однопроходность, число итераций propagation, худший случай по памяти для path coordinate matrix). Зафиксировать ли именно этот набор как обязательный тестовый корпус, или нужен другой набор?

## Answer

Фиксируем набор форм из документа как обязательный тестовый корпус:

1. **Сквозной пример §2** — 13 узлов, эталонные значения `depth`/`rank`/`size`/DFS/BFS/LCA уже посчитаны и проверены в документе (§2–§10) — готовый regression-якорь для golden-файлов (см. `[[04-corpus-golden-format]]`).
2. **Широкое дерево с фиксированной малой глубиной**: `d ≈ 10`, миллионы листьев на одной глубине — лучший случай для `parent`+`sibling`, худший для path coordinate matrix (§3.4).
3. **Вырожденная цепочка** `n = d` — худший случай по глубине/памяти для матрично-ориентированных методов (§3.4), максимум итераций для наивного propagation и LCA-подъёма.
4. **Сбалансированное широкое дерево** — типовой случай, среднее число итераций.
5. **Звезда** (один родитель, огромное число детей `c`) — нагружает `rank`/propagation по `sibling` (максимальная длина цепочки братьев, §6.2).
6. **Перемешанная перестановка §7.4** — дерево, потерявшее топологический порядок (`parent[i] <= i` не выполняется). Единственная форма, которая различает однопроходные (§5.3) и итеративные/pointer-doubling (§5.1, §5.4) реализации распространения маски — на ней однопроходная версия обязана давать *неверный* результат, и golden-файл должен это фиксировать как ожидаемое поведение, а не как баг.
7. **Испорченный набор для §13** — сознательно нарушенные инварианты (обрыв за границу, цикл `parent[i] > i`, дублирующийся `sibling`, больше одного корня, недостижимые узлы) — golden-результат здесь: какую именно проверку §13 обязаны провалить все 4 реализации.

Генерация — см. `[[04-corpus-golden-format]]`.
