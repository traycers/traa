## Question

`docs/learning/array-trees/09-lca.md` — четыре варианта, все входят в объём (`[[../../array-trees/issues/02-operation-set]]`): наивный подъём (§10.3, только `depth`), binary lifting для одной пары (§10.4, поверх ancestor table), пакетный/векторный вариант для `m` пар (§10.5, тот же ancestor table, но в векторном стиле — без ветвлений, через `where`/select), LCA целого множества `S` (§10.6, один обратный проход со счётчиками, вариант propagate-примитива с `f=+`).

Нужно решить архитектуру всех четырёх как единой категории: общая ли у наивного/binary-lifting/пакетного вариантов сигнатура запроса (пара `(a,b)` vs вектор пар), как пакетный вариант (§10.5) реализует «без ветвлений» на std (`std::vector<bool>`-маска + `select`, а не реальный SIMD — это std-таргет) и не превращается ли по факту в обычный цикл по парам, как LCA множества (§10.6) переиспользует propagate-примитив ([[01-propagate-primitive]]) с `f=+` и особым гашением самоссылки корня (граница цикла `i=1`, не `i=0`, §10.6 warning), и где заканчивается ответственность этой операции и начинается [[06-ancestor-table]] (кто строит таблицу — сама LCA-операция при первом вызове, или она получает уже построенную).

## Answer

**Правка собственного черновика тикета:** LCA целого множества (§10.6) — **не** «вариант `propagate`-примитива с `f=+`», как было сформулировано изначально. Источник явно ссылается на §5.3 (однопроходная топологическая стратегия): `cnt[parent[i]] += cnt[i]` за один обратный проход `i = n-1..1`, с явным предупреждением про границу цикла (не включать `i=0`/корень — `+=` неидемпотентна, в отличие от идемпотентной записи в однопроходной маске). Это та же категория, что однопроходные стратегии `05`, не `propagate<...>`.

**Реопен [[05-mask-propagation-strategies]] (Q21) рассмотрен и отклонён:** теперь у формы «однопроходный топологический scan» два потребителя (однопроходная маска в 05, `lca_set` здесь) — формально порог «≥2 потребителя» пройден, но общий примитив **не заводится**: механика различается на уровне цикла (маска — forward, `mask[i] = mask[i] or mask[parent[i]]`, self-комбинация на каждом шаге; `lca_set` — чистый backward scatter, `cnt[parent[i]] += cnt[i]`, без чтения собственного текущего значения). Общий примитив здесь был бы тонкой оболочкой с `forward`/`backward`-переключателем, не убирающей дублирование, а прячущей разницу за более сложным API — порог «два потребителя» эвристика, не гарантия, извлечение не окупается.

**Пакетный вариант (§10.5) на std-таргете — параллельный цикл, не буквальная безветвлевая форма источника.** `where`/select-переписывание §10.5 нацелено на SIMD (полосы одного регистра расходятся при ветвлении); эта карта — только std-таргет, параллелизм здесь — по независимым парам (потоки/задачи), где ветвление внутри одной пары не создаёт того конфликта, ради которого переписан §10.5. `lca_batch` — параллельный проход (`std::execution::par`) по `m` парам, переиспользующий ту же скалярную логику, что `lca_binary_lifting` (с ранним выходом на каждом уровне `k`, а не безусловным проходом по всем уровням для всех пар).

**`AncestorTable` строится один раз вызывающим кодом, не операцией LCA.** Ни `lca_binary_lifting`, ни `lca_batch` не строят и не кешируют таблицу сами — принимают `AncestorTable<IndexT> const&` параметром. Смысл pointer doubling — амортизировать `O(n log d)` построения по множеству запросов `O(log d)`; построение таблицы на каждый вызов свело бы обе операции к наивному подъёму без всякого выигрыша.

**Сигнатуры и возвращаемые типы (только `lca_naive` — `std::expected`, остальные три — нет):**
- `lca_naive(const Tree<T,IndexT>&, IndexT a, IndexT b) -> std::expected<IndexT, ConvergenceError>` — единственная, кто сам вычисляет `depth` внутри (по прецеденту [[07-derived-vectors]] Q17: единая точка использования, как `dfs_reorder`), а `depth` — `propagate`-based, может не сойтись;
- `lca_binary_lifting(const Tree<T,IndexT>&, const AncestorTable<IndexT>&, IndexT a, IndexT b) -> IndexT` — таблица уже построена, внутри только чтение по битам `k`, `propagate` не вызывается;
- `lca_batch(const Tree<T,IndexT>&, const AncestorTable<IndexT>&, std::vector<IndexT> const& a, std::vector<IndexT> const& b) -> std::vector<IndexT>` — то же самое, без обёртки;
- `lca_set(const Tree<T,IndexT>&, std::vector<IndexT> const& s) -> IndexT` — однопроходный `cnt`-scan, не итеративный, сходимости как понятия нет.
