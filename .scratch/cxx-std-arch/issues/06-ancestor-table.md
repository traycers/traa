## Question

Векторы предков на расстоянии `2^k` (`A1, A2, A4, ...`, `docs/learning/array-trees/04-mask-propagation.md` §5.4) нужны как минимум трижды: pointer doubling для propagation-маски ([[05-mask-propagation-strategies]] §5.4), LCA binary lifting (`09-lca.md` §10.4) и пакетный/векторный LCA для `m` пар (§10.5). Один и тот же набор таблиц обслуживает все три случая («строится один раз и обслуживает обе задачи», §10.4).

Нужно решить архитектуру этого как переиспользуемого компонента: отдельная структура/тип (`AncestorTable`) со своим построением (`K+1 = ⌈log₂ d⌉ + 1` векторов, каждый следующий — `Ak = Ak-1[Ak-1]`) и запросом («предок на расстоянии `2^k`» / «предок на расстоянии произвольного `diff`» — как в §10.4 составить `diff` из битов `k`), или каждый вызывающий код (маска, LCA-одиночный, LCA-пакетный) строит свою копию таблиц на месте? Как число уровней `K` выбирается — по фактической глубине дерева (`depth`-максимум, требует уже посчитанного [[07-derived-vectors]]) или по консервативной оценке `⌈log₂ n⌉`? Хранение — плоский массив `n × (K+1)` или вектор векторов?

## Answer

Отдельный переиспользуемый тип `AncestorTable`, которым пользуются все три потребителя (pointer doubling в [[05-mask-propagation-strategies]], одиночный и пакетный LCA в будущем [[11-lca-variants]]) вместо того, чтобы каждый строил свой набор таблиц на месте — три места используют один и тот же алгоритм построения (`Ak = Ak-1[Ak-1]`), дублировать его смысла нет.

Интерфейс запроса — только сырой доступ к уровню: `level(k) -> const std::vector<IndexT>&`. Метода-удобства «предок на произвольном расстоянии `diff` одним вызовом» нет: и pointer doubling (§5.4), и binary lifting (§10.4/10.5) в первоисточнике сами разбирают `diff`/офсет по битам `k` в собственном цикле и на каждом шаге обращаются к конкретному `Ak[i]` — композиция бит вплетена в алгоритм на стороне вызывающего кода, оборачивать её в примитив незачем.

`K` (число уровней, `K+1` векторов) вычисляется из фактической максимальной глубины дерева `d_max`, а не из консервативной оценки `⌈log₂ n⌉` — источник (`04-mask-propagation.md`, конец §5.4) прямо рекомендует брать `⌈log₂ d_max⌉` с небольшим запасом; `⌈log₂ n⌉` совпадает с этим только в вырожденном случае цепочки (`d = n`), в обычном ветвящемся дереве завышает `K` и тратит лишнюю память `4n` за уровень без пользы. Следствие: `d_max` вызывающий код обязан посчитать заранее (через `depth()` из [[07-derived-vectors]]) и передать в конструктор `AncestorTable` — таблица предков не первый примитив в графе построения, это ожидаемая зависимость.

Хранение — `std::vector<std::vector<IndexT>>`, один вектор на уровень, а не плоский `n × (K+1)` массив с ручной адресацией. Это напрямую даёт уже решённую сигнатуру `level(k) -> const std::vector<IndexT>&` без промежуточного `span`/арифметики и без риска перепутать раскладку. Единая аллокация и SIMD-дружественная плоская раскладка были бы аргументом в пользу плоского массива, но SIMD-таргет (`cxx/traaxx_simd`) вне области этой карты, а построение каждого уровня и так работает с ним целиком — вектор векторов не проигрывает в локальности для этого паттерна доступа.
