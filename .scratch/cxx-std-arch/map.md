## Destination

Зафиксированная **архитектура** (не код) для реализации в `cxx/traaxx` (только std-таргет, parallel STL — без `cxx/traaxx_simd`) полного набора операций §4–§11 из `docs/learning/array-trees/` (производные векторы включая `depth`, три стратегии propagation маски, DFS- и BFS-переупорядочивание, LCA — все 4 варианта, пять мутаций) плюс валидация инвариантов §13:

- сигнатуры функций и методов над `Tree<T,IndexT>`;
- разбиение на переиспользуемые примитивы (propagation-шаблон, ancestor table для pointer doubling, permutation/remap, битовый набор `BitMask`);
- раскладка файлов внутри `cxx/traaxx`;
- место уже существующих `Tree<T,IndexT>` и `depth()` в этой архитектуре — они не заморожены, карта может их дорабатывать/переписывать ради согласованности с остальным набором.

Сама реализация тел операций, тесты `t_traaxx` на конкретные операции и диспетчеризация по строковому `op` в `cxx/traapp` (`[[../array-trees/issues/09-cli-schema-details]]`) — отдельная работа **после** этой карты, по зафиксированной здесь архитектуре. Карта тикетов на «написать код» не заводит.

## Decisions so far

- [Общий propagate-примитив и конвергенция](issues/01-propagate-primitive.md) — один шаблонный `propagate<...>` по §6.1 для итеративных случаев (rank, маски, depth); `depth()` переписывается поверх него; категория «производные векторы» включает `depth`, не исключает. **Амендмент по [[issues/07-derived-vectors]]:** не throw, а `std::expected<T, E>` — примитив возвращает его напрямую, единый `E` (например `ConvergenceError{iterations}`) на все операции категории; тулчейн подтверждён (`clang 21.1.8`/Ubuntu 26.04, `-std=c++23`). **Правка:** `size` изначально числился потребителем `propagate<...>` (`f=+`) — неверно, см. [[issues/07-derived-vectors]] (та же природа ошибки, что LCA-множества в [[issues/11-lca-variants]]): неидемпотентная `f=+` в наивном «повторять пока не сойдётся» никогда не сходится на ветвящемся дереве.
- [Производные векторы: разбиение и `depth()`](issues/07-derived-vectors.md) — через `propagate` (→ `std::expected<vector<IndexT>, ConvergenceError>`): `depth`, `rank`; однопроходный топологический scan, не `propagate` (голый `vector`, без `expected`): `size`; прямым O(n) проходом (голый `vector`, без `expected`): `nsibling`, `isleaf` (→ `vector<bool>`), `firstchild`, `lastchild`. `size` — отдельная функция здесь (не внутри [[issues/09-dfs-reorder]]), переиспользуется тестом предка §10.7 независимо от DFS-reorder. `depth()` сохраняет сигнатуру входа, меняется только тип возврата и тело.
- [Permutation/remap-примитив](issues/08-permutation-remap.md) — свободные функции на сырых `std::vector` (`gather`, `remap_index_vector`, `inverse`), без привязки к `Tree`; `old2new` строится один раз и переиспользуется. Конвенция для DFS/BFS-reorder ([[issues/09-dfs-reorder]]/[[issues/10-bfs-reorder]]) — одно имя, две формы вызова по аналогии `std::list::sort()`/`std::sort`: свободная функция `dfs_reorder(const Tree&) -> std::expected<DfsReorderResult<T,IndexT>, ConvergenceError>` (copy-returning, read-only, тело — новый `Tree`+`new_to_old`+`old_to_new`, по требованию уже зафиксированной CLI-схемы) и метод `Tree::dfs_reorder() -> std::expected<ReorderTables<IndexT>, ConvergenceError>` (in-place, мутирует `*this`, возвращает только таблицы). `BfsReorderResult`/`bfs_reorder` — симметрично.
- [DFS-reorder](issues/09-dfs-reorder.md) — `depth`/`size` вычисляются внутри `dfs_reorder` (не аргументами); сегментированный scan вдоль `sibling` для суммы размеров левых братьев — разовый код внутри `dfs_reorder.cpp`, не отдельный примитив (единственный потребитель).
- [BFS-reorder](issues/10-bfs-reorder.md) — `depth`/`rank` вычисляются внутри `bfs_reorder`; послойный цикл (`d` проходов, `std::stable_sort` по ключу «новая позиция родителя, `rank`» на каждом уровне) — разовый код, общего примитива с DFS-reorder нет.
- [Инкапсуляция Tree<T,IndexT>](issues/02-tree-encapsulation.md) — `parent`/`sibling`/`data` приватные + `const`-аксессоры; пять мутаций — методы `Tree`, мутирующие `*this`; операции только для чтения — свободные функции над `const Tree&`.
- [BFS независимо от DFS](issues/03-bfs-independent.md) — BFS-переупорядочивание строится способом Б (§9.2, послойно), не выводится устойчивой сортировкой из DFS-порядка.
- [Раскладка файлов: один файл на операцию](issues/04-file-layout.md) — паттерн `depth.hpp`/`depth.cpp` продолжается на весь новый набор (~20 функций/методов), имена файлов близки к именам `op` из `09-cli-schema-details.md` там, где `op` уже назван схемой.
- [Таблица предков `AncestorTable`](issues/06-ancestor-table.md) — отдельный переиспользуемый тип (не ad hoc на каждом месте использования) с интерфейсом `level(k) -> const std::vector<IndexT>&` (без метода-удобства на произвольный `diff`); `K` считается из фактической `d_max` (`depth()` из [[issues/07-derived-vectors]]), не из `⌈log₂ n⌉`; хранение — `std::vector<std::vector<IndexT>>`.
- [Стратегии распространения маски + `BitMask`](issues/05-mask-propagation-strategies.md) — только итеративная построена поверх `propagate<...>`; однопроходная и pointer doubling — самостоятельный код (число итераций не детектируется сравнением состояний). Шесть публичных функций (3 стратегии × 2 направления, имена = `op` из CLI-схемы). Маска — упакованный битовый набор на словах `std::uint64_t` (не байт/узел, не `std::vector<bool>`), атомарный `fetch_or` на слово для scatter вверх; отдельный тип `BitMask` (`get`/`set`/`atomic_or`/`size`).
- [Валидация инвариантов §13](issues/13-invariant-validation.md) — восемь значений `InvariantCheck` (не семь; `bounds` объединён, `order` расщеплён на `parent_order`/`sibling_order`, разрешает несостыковку в уже зафиксированной `array-trees/08-json-schema.md`). Двухступенчатое выполнение по безопасности памяти (не эффективности): ступень 1 (`bounds`/`parent_order`/`sibling_order`/`single_root`/`sibling_injective`) всегда; ступень 2 (`sibling_same_parent`/`reachable_from_root`/`propagation_converges`, индексируют через `parent`/`sibling`) — только если `bounds` чиста, иначе UB. `reachable_from_root`+`propagation_converges` — одна пропагация (`propagate_down_iterative(seed={root})` из 05), не две. `validate_invariants(const Tree&) -> ValidationResult`, не `std::expected` (несходимость — не ошибка, а диагностируемый случай).
- [Мутации](issues/12-mutations.md) — **без инкрементальных кешей** `nsibling`/`lastchild`: каждая мутация вызывает [[issues/07-derived-vectors]] заново (`O(n)`), сознательное расхождение с заявленным в первоисточнике `O(1)` для `append`/`deleteLeaf` ради простоты `Tree` (без дополнительного приватного состояния сверх [[issues/02-tree-encapsulation]]). `append(p) -> IndexT` (id нового узла); `deleteLeaf`/`splice -> void` (предусловия — контрактные, `assert` в debug); `deleteSubtree -> std::expected<void, ConvergenceError>` (маска §5.1 + `gather`/`remap_index_vector` из 08 на уменьшившемся `n`); `move -> std::expected<void, MoveError>` (`would_create_cycle`/`tree_corrupted`), cycle-check — маска, итеративная стратегия (05), окончательно, не DFS-тест (тот полагается на инвариант порядка, который после `splice`/`move` не гарантирован).
- [LCA — все 4 варианта](issues/11-lca-variants.md) — LCA множества (§10.6) исправлено: однопроходный топологический scan (как §5.3), не `propagate<...>`; реопен 05 рассмотрен и отклонён (два потребителя формально есть, но механика форматов расходится, извлечение не окупается). Пакетный вариант (§10.5) на std — параллельный цикл по парам, переиспользующий скалярную логику `lca_binary_lifting`, не буквальная безветвлевая `where`-форма источника (та — SIMD-специфика, вне области карты). `AncestorTable` строится один раз вызывающим кодом, передаётся `const&` в `lca_binary_lifting`/`lca_batch`, они её не строят и не кешируют. Только `lca_naive` — `std::expected<IndexT, ConvergenceError>` (сама считает `depth` внутри); `lca_binary_lifting`/`lca_batch`/`lca_set` — голые значения, источников несходимости у них нет.
