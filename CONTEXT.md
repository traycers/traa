# traa

Спецификация и (после неё) реализации array-based деревьев (parent+sibling, SoA) на C++ и Go, сравниваемые между собой по корректности и скорости.

## Language

**Shape**:
Имя одной из фиксированных форм тестового дерева в корпусе (`example`, `wide-shallow`, `degenerate-chain`, `balanced-wide`, `star`, `shuffled-permutation`, `corrupted-invariants`, плюс канарейка на структурный payload). Один shape — один файл корпуса.
_Avoid_: тестовый кейс (это `case`, другое понятие), форма дерева без уточнения

**Corpus file**:
Языконейтральный JSON-файл одного дерева (`corpus/<shape>.json`): структурные вектора `parent`/`sibling`/`data`, метаданные (`shape`, `nodes_count`, `expected_valid`, `payload_type`). Порождается единственным каноническим генератором, не по одному на язык.
_Avoid_: golden-файл (это результат операции, не сам корпус), тестовое дерево без уточнения формата

**Payload type**:
Самоописание типа `T` внутри corpus file (`payload_type`): `{"kind": "primitive", "value": <имя типа>}` для скаляра или `{"kind": "struct", "value": {...}}` для структуры, рекурсивно. Позволяет реализации на старте узнать, какой generic-инстанс дерева поднимать для конкретного corpus file, не читая код теста.
_Avoid_: тип данных, схема данных (слишком общо)

**Case**:
Именованный вызов одной операции с конкретными аргументами поверх конкретного дерева — один файл `cases/<shape>/<case_id>.json`, `{"op", "args"}` (`case_id` — имя файла). Один shape может нести много case — например, разные пары для LCA или разные стратегии propagation на одном дереве.
_Avoid_: тест, сценарий, запрос

**Golden file**:
Эталонный результат одного case (`golden/<shape>/<case_id>.json`), всегда `{"result": <value>}`. Реализации golden не производят — только читают corpus+case и отдают результат по CLI-контракту; сравнение с golden делает внешний драйвер.
_Avoid_: ожидаемый результат без уточнения формата, эталон

**Benchmark manifest**:
Список сценариев `[{"tree", "case", "repeat"}, ...]`, передаваемый CLI-раннеру флагом `--manifest` за один вызов процесса — чтобы разобрать каждый уникальный corpus-файл только один раз на весь набор сценариев, а не по разу на сценарий. Только для бенчмарков; для проверки корректности используется одиночный режим (`--tree`/`--case`).
_Avoid_: батч, набор тестов
