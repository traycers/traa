# 12–14. Сводка, инварианты и сложность

## 12. Четыре порядка и их свойства

Все четыре описывают одно и то же дерево ([«06. Перестановки»](06-permutations.md) §7.4) — различаются только тем, что каждый из них даёт даром:

| Свойство | Произвольный | Порядок создания | DFS | BFS |
|----------|:------------:|:----------------:|:---:|:---:|
| Корень может быть в любой позиции | **да** | нет, только 0 | нет, только 0 | нет, только 0 |
| Можно строить инкрементально и конкурентно | нет | **да** | нет | нет |
| `parent[i] <= i` (топологический) | нет | да | да | да |
| Однопроходный propagation ([«04. Распространение маски»](04-mask-propagation.md) §5.3) | **нет** | да | да | да |
| Поддерево — непрерывный диапазон | нет | нет | **да** | нет |
| Дети — непрерывный диапазон | нет | нет | нет | **да** |
| Уровень — непрерывный диапазон | нет | нет | нет | **да** |
| `parent` неубывающий | нет | нет | нет | **да** |
| `sibling` избыточен | нет | нет | **да** | **да** |
| «`a` предок `b`?» за `O(1)` | нет | нет | **да** | нет |
| Типичная фаза использования | — | запись дерева | финализация, индексирование | послойные обходы |

Первый столбец — не гипотетический: это то, что представление допускает само по себе, без дополнительных соглашений. Остальные три — соглашения, которые накладываются сверху ради конкретной выгоды из соответствующего столбца.

Практический вывод: **порядок создания — для записи, DFS/BFS — для чтения**. Переупорядочение выполняется один раз, когда дерево перестало меняться, — и вместе с ним сохраняются обе таблицы соответствия ([«06. Перестановки»](06-permutations.md) §7.2), чтобы ссылки на исходные id оставались разрешимыми.

## 13. Инварианты и валидация

Дерево может прийти повреждённым (с диска, по сети, из другого процесса). Проверки, каждая — один проход по массивам, все дёшевы по сравнению с последствиями пропуска:

| Инвариант | Проверка | Что ловит |
|-----------|----------|-----------|
| `parent[i] < n`, `sibling[i] < n` | сравнение | выход за границы, битые данные |
| `parent[i] <= i`, `sibling[i] <= i` | сравнение | нарушение порядка создания; **гарантирует ацикличность** — цикл требует ссылки вперёд |
| Ровно один узел с `parent[i] == i` | подсчёт | лес вместо дерева, потерянный корень |
| `sibling[i] != i` => `parent[sibling[i]] == parent[i]` | gather + сравнение | «сосед» из чужой ветки |
| `sibling` инъективен на не-первых детях | подсчёт вхождений | два узла, объявившие себя правым соседом одного и того же |
| Все узлы достижимы из корня | propagation вниз от корня | висячие поддеревья |
| Сходимость propagation за `<= n` итераций | счётчик итераций ([«05. Propagation pattern»](05-propagation-pattern.md) §6.2) | всё остальное, что превратило бы цикл в вечный |

Проверка `parent[i] <= i` заслуживает выделения: она одновременно даёт ацикличность (доказательство по индукции: цепочка `parent` строго убывает, значит конечна и упирается в корень) и разрешает однопроходные версии propagation ([«04. Распространение маски»](04-mask-propagation.md) §5.3). Одно сравнение окупает и то, и другое.

После любого переупорядочения ([«07. DFS-порядок»](07-dfs-order.md), [«08. BFS-порядок»](08-bfs-order.md)) прогон этих же проверок на новых векторах ловит ошибку «переставили, но не перевели» из [«06. Перестановки»](06-permutations.md) §7.3.

## 14. Сложность и память

`n` — число узлов, `d` — глубина, `c` — максимальное число детей у одного родителя.

| Операция | Память | Последовательно | Параллельно (число проходов) |
|----------|--------|-----------------|------------------------------|
| Хранение (`parent` + `sibling`, uint32) | `8n` байт | — | — |
| path coordinate matrix | `4nd` байт | — | — |
| Маска поддерева / предков | `n` бит | `O(n)`, 1 проход | `O(d)` или `O(log d)` с удвоением |
| `depth` | `4n` | `O(n)`, 1 проход | `O(d)` / `O(log d)` |
| `rank` | `4n` | `O(n)`, 1 проход | `O(c)` / `O(log c)` |
| `size` (поддеревья) | `4n` | `O(n)`, 1 проход | `O(d)` |
| DFS, способ A (матрица) | `4nd` | `O(nd log n)` | `O(d + log n)` |
| DFS, способ B (смещения) | `O(n)` | `O(n)` при известных `size` | `O(d)` |
| BFS из DFS | `O(n)` | `O(n)` (counting sort по `depth`) | `O(1)` сортировок |
| Применение перестановки к вектору | `4n` | `O(n)` | 1 проход |
| `LCA(a, b)`, наивный подъём | `4n` (`depth`) | `O(d)` | — |
| `LCA(a, b)`, binary lifting | `4n(K+1)`, `K = ⌈log₂ d⌉` | `O(log d)` | — |
| `LCA` для `m` пар пакетом | `4n(K+1) + 8m` | `O(m log d)` | `2(K+1)+1` проходов |
| `LCA` множества `S` | `4n` | `O(n)`, 1 проход | `O(d)` |

Стоимость мутаций (добавление, удаление, перемещение) — отдельная таблица, [«10. Изменение дерева»](10-mutations.md) §11.8.

Отдельно про однопроходные варианты: они возможны **только** благодаря инварианту `parent[i] <= i`. Для дерева с произвольной нумерацией все строки колонки «последовательно» превращаются в `O(n·d)`.
